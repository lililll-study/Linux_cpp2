# 一 TCP-server

## 1 创建TCP server

(1) 创建套接字

```c
sock(AF_INEF, SOCK_STREAM, 0)
- 0表示自动选择协议类型
```



(2) 创建sockaddr_in地址，设置好<mark>服务器</mark>的端口号和IP

```c
    struct sockaddr_in servaddr;
    servaddr.sin_family = AF_INET;
    servaddr.sin_port = htons(2000);//0-1023不能用，要大于1024
    servaddr.sin_addr.s_addr = htonl(INADDR_ANY); //0.0.0.0
```



(3) 绑定套接字和服务器的地址

```c
bind(sockfd, (struct sockaddr*)&servaddr, sizeof(struct sockaddr_in))
这里绑定的是服务器自己，绑定IP: 0.0.0.0 (所有网卡) port：2000
现在这个socket代表：服务器上的2000端口
```



(3) listen监听套接字

```c
listen(sockfd, 10)
- 10(backlog)：表示允许最多 10 个 连接在队列中等待被 accept() 处理。
这里的第二个入参维护两个队列：
半连接和全连接队列。
半连接：完成一次TCP握手但是没有全部握手完成的队列
全连接：完成全部三次握手的队列，可以由accept()取出的队列
```

创建流程解析：

也就是说一个套接字，绑定的是自身的服务地址，当开始监听这个套接字时，可以从这个套接字接收很多客户端。服务器通过accept监听套接字，接收客户端来的连接，创建很多的client_fd。

listen之后，这时候客户端可以发送数据，但是，服务端需要recv后才会打印数据。

(4) 创建客户端连接

```c
使用accept创建一个客户端连接
int clientfd= accept(sockfd, (struct sockaddr*)&clientfd, &client_len)
```

这时候grep 2000会出现第二个tcp的端口服务，代表连接建立。



(5) 接受数据

```c
datalen = recv(clientfd, buffer, buffer_size, 0)
```

### 1.1 问题

```c
    while(1) {
        int clientfd = accept(sockfd, (struct sockaddr*)&client_addr, &client_len);
        printf("accept finished\n");

        char buffer[BUFFER_LENGTH] = {0};
        int data_len = recv(clientfd, buffer, BUFFER_LENGTH, 0);
        printf("recv buffer: %s\n", buffer);

        int send_len = send(clientfd, buffer, data_len, 0);
        printf("send len: %d\n", send_len);
    }
```

**现象**：如果有多个客户端同时创建连接，但是没有发送数据，从last客户端依次向first客户端发送数据，发现first客户端发送完后，所有客户端都收到了数据；first没发送数据，则所有客户端都收不到数据。

**分析**：如上代码，因为当first客户端连接创建后，程序会阻塞在recv处。这之后的客户端连接仍然建立(TCP三次握手在内核中完成，独立于程序)，但是由于卡在了接收处，所以客户端数据无法接收。

**解决方案**：多线程

## 2 一请求一线程

相当于把接收数据这个任务，作为线程任务丢给线程去做了，主线程只考虑accept创建客户端的文件描述符。

```c
主循环
// 创建线程并执行任务，用于执行接收客户端数据的任务
pthread_t th_id;
pthread_create(&th_id, NULL, client_thread, &clientfd);
```

新建一个线程入口

```c
// 客户端处理线程 （写入线程要执行的任务）
void *client_thread(void *arg) {
    int clientfd = *(int *)arg;

    while (1) {
        char buffer[BUFFER_LENGTH] = {0};
        int data_len = recv(clientfd, buffer, BUFFER_LENGTH, 0);
        printf("recv buffer: %s\n", buffer);

        int send_len = send(clientfd, buffer, data_len, 0);
        printf("send len: %d\n", send_len);
    }

}
```

结果：实现了多个客户端连接后，可以同时发送数据，并被服务器接收打印。



服务器的并发值指的就是IO的并发（即IO做到100w的数量）。每个进程的IO数量有限制，可以通过下面的命令查看当前进程的IO数量。<mark>在Linux中，一切皆文件描述符（fd）</mark>。在增加客户端的时候，fd是依次增加的。


## 3 IO多路复用（select/poll/epoll）

1 构建fd集合

```c
    fd_set rfds;
    FD_ZERO(rfdss);
    FD_SET(sockfd,rfdsds);
```

把需要用到的sockfd在fd集合中置位。



2 select

带有五个参数，输入可读集合，用于判断集合中的哪个fd有数据了（此处判断哪个fd是否可读）。返回一个三个总集合被设置的文件总数。

1.**每次调用select，需要把fd_set从用户空间copy进内核空间。如果是100w，则每次需要复制100w/8个，大约13w个字节。**

2.**遍历所有的fd，到最大的maxfd。遍历的过程是一个循环。**

- 超时时间可以设置，如果为null，则一直阻塞等待事件

```bash
timeout的作用：
如果设置了等待时间，那么等待了n秒没有事件，就立即返回，可以做其他事情
```

```c
int nready = select(maxfd+1, &rfds, NULL. NULL, null)
最大fd数量，可读集合，可写集合，错误集合，超时时间
***
比如说传入
34567 是否可读
3和4可读
678 是否可写
7可写
则nready = 3
```

入参三个集合的含义

```c
int select(int nfds, 
           fd_set *readfds,   // ① 可读事件集合
           fd_set *writefds,  // ② 可写事件集合
           fd_set *exceptfds, // ③ 异常事件集合
           struct timeval *timeout);
nfds是总的clientfd数量。
readfds这些集合，通过FD_SET进行置位，然后在select中进行循环判断。
```

### 3.2 poll

1 结构体变量pollfd

```c
struct pollfd {
    int fd;            要监控的fd
    short events;      期望监控的事件(输入)
    short revents;     实际发生的事件(输出)
}
```

- events：告诉内核"我想监控什么事件"

```c
pfd.events = POLLIN;  // 监控可读事件
// 可以组合多个事件
pfd.events = POLLIN | POLLOUT;  // 监控读和写
```

- revents：内核告诉我们"发生了什么事件"

```c
if (pfd.revents & POLLIN) {
    // 有数据可读
    recv(pfd.fd, ...);
}
if (pfd.revents & POLLOUT) {
    // 可以写入
    send(pfd.fd, ...);
}
```



2 构建poll    ——while事件循环内

```c
int nready = poll(fds, maxfd+1, -1);
fd集合    fd的大小  timeout（-1代表一直阻塞）
```

一共三个入参，此处检测fds中的0~maxfd+1范围中，是否有可读事件，有的话把事件数量返回。

3 判断sockfd的客户端连接

```c
        if (fds[sockfd].revents & POLLIN) {
            int clientfd = accept(sockfd, (struct sockaddr*)&client_addr, &client_len);
            printf("accept finished clientfd: %d\n", clientfd);

            fds[clientfd].fd = clientfd;
            fds[clientfd].events = POLLIN;

            if (clientfd > maxfd) maxfd = clientfd;

        }
```

监听sockfd通过有事件来了，说明有新连接。接着accept一个clientfd，并把这个客户端fd加入到fds集合中

作为下一次poll判断的新fd。

4 遍历所有客户端

跳过了sockfd，直接遍历客户端fd，一旦客户端检测到可读事件，则读取数据。并进行连接判断，**<mark>如果断开则需要把fd置为-1（无效标识，poll遍历fds时会跳过），并把事件清空。</mark>**

```c
        int i = 0;
        for (i = sockfd+1; i <= maxfd; i++) {
            if (fds[i].revents & POLLIN) {
                char buffer[BUFFER_LENGTH] = {0};
                int data_len = recv(i, buffer, BUFFER_LENGTH, 0);

                if (data_len == 0) { // 断开连接了
                    // close(clientfd);
                    printf("client disconnect: %d\n", i);
                    close(i);

                    fds[i].fd = -1;
                    fds[i].events = 0;

                    continue;
                } else if (data_len < 0){  // 读取出错
                    printf("read error: %d\n", i);
                    close(i);
                    continue;
                }
                printf("recv buffer: %s\n", buffer);
                int send_len = send(i, buffer, data_len, 0);
                printf("send len: %d\n", send_len);
            }
        }
```





### 3.3 epoll📌📌

1 创建epoll

```c
int epfd = epoll_create(10)
```

- 入参（无效参数）传多大不影响返回值，只要设置一个！=0的即可
  
  

2 初始化epoll_event结构体

```c
struct epoll_event {
    _poll_t events;
    _u64 data;
} EPOLL_PACKED;
```



while事件循环内

3 epoll_wait等待

```c
        struct epoll_event events[1024] = {0};
        int nready = epoll_wait(epfd, events, 1024, -1);
```



4 处理连接以及客户端数据 accept & recv

（1）通过events[i].data.fd来获取一个客户端连接

（2）accept连接后，把events重新置为events ，data.fd设置为clientfd，然后把这个客户端fd用epoll_ctl函数加入到epfd中。

（3）如果连接不等于sockfd，判断这个fd的事件是否被置为可读。如果可读，则recv取出数据。如果是断开连接，则epoll_ctl调用EPOLL_CTL_DEL从epfd集合中删除这个fd

```c
for (i = 0; i < nready; i++) {

    int connectionfd = events[i].data.fd;

    if (connectionfd == sockfd) {

        int clientfd = accept(sockfd, (struct sockaddr*)&client_addr, &client_len);
        printf("accept finished clientfd: %d\n", clientfd);

        evevents = EPOLLIN;
        ev.data.fd = clientfd;
        epoll_ctl(epfd, EPOLL_CTL_ADD, clientfd, &ev);

    } else if (events[i].events & EPOLLIN) {

        char buffer[BUFFER_LENGTH] = {0};
        int data_len = recv(connectionfd, buffer, BUFFER_LENGTH, 0);

        if (data_len == 0) { // 断开连接了
            // close(clientfd);
            printf("client disconnect: %d\n", connectionfd);
            close(connectionfd);
            epoll_ctl(epfd, EPOLL_CTL_DEL, connectionfd, NULL);

            continue;
        } else if (data_len < 0){  // 读取出错
            printf("read error: %d\n", connectionfd);
            close(i);
            continue;
        }
        printf("recv buffer: %s\n", buffer);
        int send_len = send(connectionfd, buffer, data_len, 0);
        printf("send len: %d\n", send_len);
    }

```

| 特性            | select     | poll       | epoll           |
| ------------- | ---------- | ---------- | --------------- |
| **诞生时间**      | Unix（1983） | Unix（1986） | Linux 2.6（2002） |
| **数据结构**      | fd_set（位图） | pollfd（数组） | 事件表（红黑树）        |
| **最大fd数**     | 1024（可修改）  | 无限制        | 无限制             |
| **时间复杂度**     | O(n)       | O(n)       | O(1)            |
| **内核通知方式**    | 轮询所有fd     | 轮询所有fd     | 事件驱动回调          |
| **用户态/内核态拷贝** | 全部拷贝（3次）   | 全部拷贝（3次）   | 选择性拷贝（1次）       |
| **fd_set修改**  | ✅ 会修改      | ❌ 不修改      | ❌ 不修改           |
| **水平触发**      | ✅ 默认       | ✅ 默认       | ✅ 支持            |
| **边缘触发**      | ❌ 不支持      | ❌ 不支持      | ✅ 支持            |
| **触发机制**      | 每次遍历       | 每次遍历       | 事件回调            |
| **适用场景**      | 少量连接       | 中等连接       | 大量连接            |

为什么用Linux来做服务器很核心的重点就是，**在Linux2.6版本以后引入了Epoll**。使得server端对IO的数量能做到更多。
