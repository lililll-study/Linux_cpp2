# 一 Posix API与网络协议栈

## 1 建立连接

### （1）socket

有两个部分所组成，一个是fd的分配，还有一个是tcp控制块tcb的分配。

fd：**fd 实际上是一个整数，是进程文件描述符表的索引**

tcb：四元组，状态管理（TCP状态 以及重传信息），发送缓冲区接收缓冲区等。

```bash
用户空间                    内核空间
   |                          |
应用层 --socket()-->     分配 fd + 创建 socket 结构
   |                          |
   | --bind()-->         绑定 IP + Port
   |                          |
   | --listen()-->        创建监听队列
   |                          |
   | --accept()-->        完成三次握手，分配新 socket
   |                          |
   | --read/write-->      通过 fd 找到 socket 结构
   |                          |
   | --close()-->         释放 fd 和 socket 结构
```



### （2）bind

是一个set的过程，通过fd找到对应tcb，然后再把端口设置进tcb。

<mark>这里是把服务端的sockfd和本地起的端口地址，绑定在一起。告诉客户端你需要把数据发送到这个端口。</mark>

<mark>而connect是客户端使用的，用于绑定远程的服务器地址。</mark>

<mark>用了connect之后，客户端 的发送函数可以用send，如果没有connect，就要用sendto。</mark>





### （3）listen

把tcb中的status设置为listen，作用如下：

a. tcb -> status = TCP_STATUS_LISTEN

b. tcb -> 半连接队列(syn-queue) 和 全连接队列(accept-queue)

**syn-queue**：存放收到 SYN 但尚未完成三次握手的连接

**accept-queue**：存放已完成三次握手的连接，等待应用层调用 accept()



listen的第二个参数backlog的作用：

最开始的sys_que发展到sys+accept队列的总长度，到最后是accept队列的长度

### （5）问题

1 TCP连接的生命周期从什么时候开始？

从socket创建fd的时候开始

```bash
// 用户空间
int sockfd = socket(AF_INET, SOCK_STREAM, 0);

// 内核操作
// 1. 分配 fd
// 2. 分配 struct file
// 3. 分配 struct socket
// 4. 分配 struct sock (TCB)
// 5. 初始化 TCB
// 6. 状态: CLOSED
```

2 第三握手数据包，如何从半连接队列查找匹配的节点？

通过四元组来查询。TCP头有sport，dprot。IP协议里有sip，dip。

```bash
客户端发送 ACK (第三次握手)
    ↓
网卡中断 → IP层 → TCP层
    ↓
tcp_v4_rcv() 接收数据包
    ↓
查找对应的 sock
    ↓
tcp_v4_do_rcv() 处理
    ↓
tcp_rcv_state_process() 处理 TCP 状态
    ↓
tcp_v4_syn_recv_sock() 
    ↓
查找半连接队列 → 找到 request_sock
    ↓
验证匹配 → 创建新 sock
    ↓
从半连接移除 → 加入全连接队列
```



3 syn泛洪

listen (fd,  backlog) ;

backlog: 设置syn_que队列的长度——老版本——防止泛洪（鸡肋）

                syn + accept队列总长度，未被分配fd的tcb数量——新版本

                accept队列长度 ——新版本
