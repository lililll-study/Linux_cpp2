# 1 百度搜索

![c4ef6352-3e07-4412-8d71-fe7172384387](file:///U:/linux_first/02%20%E9%AB%98%E6%80%A7%E8%83%BD%E7%BD%91%E7%BB%9C/pictures/c4ef6352-3e07-4412-8d71-fe7172384387.png)

输入内容后点击百度一下，向server发送如下request请求：

1 广告请求：advertisement_request

2 百度ai的请求：AI_ansys(搜索内容)

3 请求搜索相关链接的列表：relevant_list

4 热搜的请求

5 相关搜索的请求

```bash
用户输入"周杰伦" → 点击"百度一下"
                │
                ▼
    ┌─────────────────────────────────────────────────────────────────┐
    │  前端（浏览器/App）                                            │
    │  同时发起 N 个请求（并行）                                      │
    ├─────────────────────────────────────────────────────────────────┤
    │  ① 广告请求      → 返回广告列表                                │
    │  ② AI 问答请求   → 返回 AI 生成的内容（可能较慢）              │
    │  ③ 搜索结果列表  → 返回相关链接（核心）                        │
    │  ④ 热搜请求      → 返回热搜词                                  │
    │  ⑤ 相关搜索请求  → 返回相关搜索词                              │
    └─────────────────────────────────────────────────────────────────┘
                              │
                              ▼
    ┌─────────────────────────────────────────────────────────────────┐
    │  前端渲染：                                                    │
    │  ├─ 先渲染广告（如果请求快）                                   │
    │  ├─ 再渲染搜索结果（核心内容）                                 │
    │  ├─ AI 结果可能较慢 → 显示加载动画，等返回后再填充             │
    │  └─ 页面最终完成 ✅                                            │
    └─────────────────────────────────────────────────────────────────┘
```

### 为什么这样设计？

| 设计原则      | 说明                                |
| --------- | --------------------------------- |
| **并行请求**  | 5 个请求同时发出，总耗时 ≈ 最慢的那个请求，而不是 5 个之和 |
| **渐进式渲染** | 哪个请求先回来就先渲染哪个，用户不用等所有请求都完成        |
| **降级策略**  | 某个请求失败（比如广告超时），不影响其他内容的展示         |
| **懒加载**   | 非关键内容（如相关搜索）可以延迟加载                |

    │  ⑧ 配送信息（预计送达时间、运费）                              │
