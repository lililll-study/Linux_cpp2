## 1 协程设计原理与实现

### （1）实现背景

#### a. 实现背景

    epoll + io非阻塞模式下（异步回调）

```c
while (1) {
    int nready = epoll_wait(epfd, events, 1024, -1);
    for (i=0; i<nready; i++) {
        if (events[i].events & EPOLLIN) {
            recv_cb(events[i].data.fd) // 回调函数
            }
        }
}
```

这种情况下，代码被撕碎了，一个完整的业务逻辑被拆分成多个回调函数，难以维护。



    例如需要完成一个：接收客户端请求 —> 查数据库 —> 调用第三方API —> 返回response的过程

用epoll实现如下：问题是，业务逻辑被拆分了，很复杂

```c
void recv_cb(int fd) {
    recv(fd, request, ...);
    // 发起查询请求
    db_query_async(request, db_cb); // 跳转第二步
}

void db_cb(result) {

    // 处理 DB 结果...
    // 发起 HTTP 请求（非阻塞）
    http_request_async(url, http_cb);  // ← 跳到步骤3
}


// 步骤3：HTTP 请求完成
void http_cb(response) {
    // 处理 HTTP 结果...
    send(fd, response, ...);  // 返回
}
```



因此协程需要实现的是：<mark>用同步的编程方式，实现异步的性能。</mark>

实现方法如下：

```c
void handle_client(int fd) {
    char request[1024];
    recv(fd, request, 1024);           // ← 看起来是阻塞的，实际上会“让出”CPU
    
    char *db_result = db_query(request); // ← 看起来是同步的，实际会“让出”CPU
    
    char *http_result = http_request(db_result); // ← 看起来是同步的，实际会“让出”CPU
    
    send(fd, http_result, len);        // ← 返回
}
```

### （2）协程原语（本质就是下面三个函数）

| 原语         | 作用                       | 类比              |
| ---------- | ------------------------ | --------------- |
| **create** | 创建一个协程，分配栈空间，初始化上下文      | 招一个临时工          |
| **resume** | 启动或恢复一个协程的执行             | 喊一声“继续干活！”      |
| **yield**  | 当前协程主动让出 CPU，切换到调度器或其他协程 | 说一句“我先歇会儿，让别人干” |

另外两个辅助原语：

* **exit**：协程执行完毕，自动销毁

* **schedule**：调度器，决定下一个运行哪个协程



协程切换的本质是：保存当前寄存器状态，加载另一个协程的寄存器状态
